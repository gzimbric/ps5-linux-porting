# Firmware 11.60 status

Last updated: 2026-10-15

Console class: regular PS5

Overall status: research in progress. Linux has not booted.

Current direction: reconstruct Sonic's coupled loader architecture on top of
the official PS5 Linux loader. The pLinux-derived wake wrapper is superseded.
The bounded implementation sequence is in the
[11.60 reconstruction plan](11.60-reconstruction-plan.md).

## Last captured full attempt

The last useful log reached these checkpoints:

```text

```

There was no later marker. The console stopped responding. This does not prove

the bypass and Linux attempt as separate userland-visible stages.

## Superseded candidate: pLinux-derived wake wrapper

The candidate changed the ordering rather than treating the previous silence
as another offset problem:

1. Before rest mode, load the Linux inputs and retain page-granular physical
   source copies plus a compact resume parameter block.
2. Hook the 11.60 S3 `HV_MP_STARTUP_CALL` resume path with a position-independent
   kernel-text wrapper.
3. On wake, call the displaced startup function with its original arguments.
4. Complete and verify the exact 16-of-16 Byepervisor strike.
5. Restore the resume hook before attempting the irreversible handoff.
6. Build the identity PML4, clone the live hypervisor high mappings, and refresh
   the Linux payload, bzImage, and initrd from the retained copies.
7. Validate the live VMMCALL handler, install the transition redirect, and use
   the kernel all-core rendezvous to enter the hypervisor shellcode.
8. On success, continue directly to Linux; do not return to GameOS userland.

It followed the original loader's broad timing, but later disassembly showed
that it did not follow the original memory contract or component boundaries.
It is no longer the candidate to test.

## 2026-10-15 loader boundary results

A loader-only build read the complete 12,702,720-byte bzImage and
54,367,236-byte initrd, printed the final fetch checkpoint, and exited normally.
The corresponding full pLinux-derived build repeatedly stopped immediately
after printing the initrd-read checkpoint. The same boundary reproduced with:

- a 28,777,476-byte trimmed initrd;
- split and reverse-split source allocations; and
- direct-memory backing after the allocation size was reduced enough to fit.

These results do not show that a coupled payload is too large. The supplied
13.60 ELF is itself coupled and performs more pre-suspend mapping work. They
show that the current pLinux-derived full ELF has a layout, state, or latent
memory defect that the loader-only build does not expose.

## Architectural comparison

The upstream source confirms the intended sequence: prepare the resume
shellcode, arm the firmware-specific HV path, request rest, then let the resume
shellcode stage Linux and invoke the all-core VMMCALL rendezvous without a
second userland payload.

An independently supplied ELF reported to support firmware 13.60 provides a
second, binary-level comparison. Its outer ELF is 237,448 bytes with SHA-256
`e51a0298cb2c97b71be0ddad9f070b574c110c899d9fe513562355272fc81226`.
The symbols and disassembly show:

- `main` prepares `shellcode_kernel_bin`, selects `hv_defeat_13xx`, requests
  rest, and then waits;
- the embedded 26,896-byte resume shellcode accepts the 13.xx firmware range;
- its boot routine patches the HV entry, installs the identity map and HV
  shellcode, stages `linux_info`, bzImage, and initrd; and
- the same resume entry then calls the all-core rendezvous.

That ELF is not evidence that the 11.60 offsets or transition are correct. It
is evidence that coupling HV defeat and Linux boot within one resume flow is
the established architecture rather than an arbitrary new design. Deeper
reconstruction also established that its root-0 AP payload only modifies the
VMCBs; a separately installed kernel wake shellcode copies `linux_info` to
physical `0x100005000`, copies bzImage to `0x100009000`, places initrd after its
aligned end, installs the HV transition at `0x100003000`, and starts the final
all-core `vmmcall(1)` rendezvous. See
[Sonic 13.60 binary reference](sonic-13.60-reference.md).

## Superseded source state

The local 11.60 branch is based on pLinux5-NG commit
`d5bd6b9f45c465e466e1e97083c9f162b94aad2c`, with a large uncommitted research
diff. It contains parameterized takeover addresses, runtime bypass validation,
the VMMCALL-specific handler path, and the new wake-coupled wrapper.

The candidate builds cleanly. The wrapper is 2,392 bytes, contains one expected
patch marker, has no final ELF relocations, and is byte-identical when extracted
from the final ELF. Its object contains only PC-relative relocations. The exact
11.60 `HV_MP_STARTUP_CALL` wrapper ABI was also confirmed from the kernel-text
dump: startup ID arrives in `RDI`, payload VA in `RSI`, and payload CR3 in
`RDX`; the wrapper maps them to `EDX`, `RCX`, and `RBX`, sets `EAX=0xF`, issues
`VMMCALL`, and returns with a balanced frame.

The first independent audit found two pre-hardware blockers: seven required
wake parameters were left zero and a handler-byte table was not truly
position-independent. Both were fixed before the hashes below were produced.
The same correction also replaced APIC-ID stack indexing and CPU-zero BSP
selection with compact arrival slots and an atomic single-boot election. See
[the candidate audit](11.60-candidate-audit.md).

A second adversarial audit rebuilt the then-current source and verified all five
targeted corrections: the complete wake parameter block, original-startup
ordering and ABI, wrapper position independence, compact arrival slots and
atomic boot election, and the cave/blob bounds. It found no surviving blocker
or new regression within that narrow static scope. Its qualified-GO disposition
is withdrawn after the later hardware failures and Sonic-first architecture
review.

## Next experiment

Do not send another variant of the superseded wrapper. Build a clean
Sonic-shaped tree from the official loader, importing only the already
hardware-validated 11.60 Byepervisor offsets/hook and VMCB discovery. Bring it
up in bounded stages:

1. official loader fetch behavior;
2. `install_page_syscore` aliases for `linux_info`, bzImage, and initrd;
3. high-firmware `prepare_resume` without arming rest mode;
4. the 11.60 AP/VMCB strike with the original startup flow preserved; and
5. the complete kernel wake shellcode and Linux transition.

The first new hardware artifact should be independently disassembled and
compared with the 13.60 reference before it is sent. The 11.60 display offsets
remain unavailable, so initial success may be headless or UART-only.
