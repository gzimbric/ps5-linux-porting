## Current source state

The local 11.60 branch is based on pLinux5-NG commit
`d5bd6b9f45c465e466e1e97083c9f162b94aad2c`, with a large uncommitted research
diff. It contains parameterized takeover addresses, a two-stage operator flow,
runtime bypass validation, staged diagnostics, and the VMMCALL-specific handler
path.

The current configuration selects the reversible HV-handler passthrough
self-test. It is not configured as a final Linux takeover build. This is
intentional while the handler redirect remains unproven.

## Next experiment

Do not repeat the full takeover yet. First run the reversible
VMMCALL-handler passthrough diagnostic:

1. validate the exact live handler bytes;
2. copy the displaced instructions into a dump-verified nearby executable
   cave;
3. redirect the handler to that cave;
4. issue one balanced VMMCALL on all CPUs;
5. return through the original handler;
6. restore and verify every modified hypervisor byte;
7. return to userland with a PASS marker.

If that returns, the remaining fault is after the passthrough portion, most
likely in the identity-CR3 transition or staged shellcode entry. If it fails,
the fault is in the live handler redirect itself and the Linux boot code is not
yet involved.
