# 11.60 wake-coupled candidate audit

Date: 2026-10-15

> **Superseded:** later hardware runs and deeper analysis of Sonic's 13.60 ELF
> invalidate this document's qualified-GO disposition. The candidate repeatedly
> stopped immediately after the initrd-read checkpoint, and its custom wake
> wrapper is not a source-level recreation of Sonic's coupled design. Preserve
> this audit as a record of what was checked, but do not send the listed
> candidate again. See [Sonic 13.60 binary reference](sonic-13.60-reference.md)
> and [Firmware 11.60 status](11.60-status.md).

Scope: static review, clean cross-build, relocation/disassembly checks, and
comparison with the upstream loader and an independently supplied 13.60 ELF.
No candidate binary has been run on hardware.

## Why the flow changed

The last 11.60 attempt completed the bypass in one phase, returned to GameOS
userland, and attempted Linux in another. The upstream loader does not use that
separation. Its resume shellcode prepares Linux, patches the HV transition, and
immediately invokes the all-core VMMCALL rendezvous.

The supplied 13.60 comparison ELF has the same architecture. Its outer `main`
prepares the resume shellcode and requests rest. The embedded resume entry then
patches the HV path, installs the identity map and HV loader, copies the Linux
inputs, and invokes the rendezvous without returning to a second userland
payload.

The 11.60 candidate now preserves that ordering while retaining the
firmware-specific 16-core Byepervisor strike and its exact verification.

## First audit findings and fixes

Two findings were hardware blockers:

1. Seven addresses required by the wake wrapper were never copied into its
   parameter block. The wrapper would reject the block and skip the displaced
   MP-startup call. The loader now fills every address and refuses to arm when
   any required handoff field is zero.
2. A static expected-byte table generated an absolute reference even though
   the final wrapper had no remaining ELF relocations. The table is now local,
   the wrapper is built with PIC flags and no red zone, and the object contains
   only PC-relative relocations.

The same pass removed two topology assumptions:

- stack pages are assigned by compact atomic arrival slot rather than APIC ID;
- the Linux bootstrap CPU is elected atomically rather than assuming APIC ID
  zero is present exactly once.

The loader and wrapper also have compile-time assertions for the shared
parameter and retained-copy page layouts.

The wake wrapper now validates that all 25 bytes of the dump-backed HV cave are
still `0xCC` before changing either live HV location. It checks relative-jump
reachability before writing, writes the cave before making the handler point to
it, and restores both locations if the supposedly non-returning rendezvous
returns.

## Second-pass disposition

An independent second adversarial pass rebuilt the final source and verified
the complete wake parameters and arm-time gate, original-startup ordering and
11.60 VMMCALL ABI, wrapper PIC properties, compact arrival slots and atomic
boot election, and every cave/blob size bound. It found no surviving first-pass
blocker and no new regression.

The pass also independently analyzed the supplied 13.60 comparison ELF. Its
observed sequence is HV patch, identity-CR3 switch, Linux staging, all-core
rendezvous, 16-core barrier, single-core election, and Linux jump in one S3
wake context. It uses the same hard-16 barrier and per-core `stgi`/SVME teardown
shape. This supports the candidate's architecture; it does not prove that the
11.60 addresses, retention assumptions, or first hardware transition work.

Historical disposition: **qualified GO for one supervised, capture-ready
hardware test**. That test disposition is now withdrawn. Subsequent hardware
results did not reach the wake wrapper, and binary-level reconstruction exposed
larger architectural differences from the known-working reference.

## Confirmed static properties

- The `HV_MP_STARTUP_CALL` ABI was checked against the 11.60 kernel-text dump.
  It maps the three incoming arguments to `EDX`, `RCX`, and `RBX`, sets
  `EAX=0xF`, issues `VMMCALL`, and returns with a balanced frame.
- The wake wrapper calls the original startup routine before it validates the
  optional Linux-takeover fields.
- All required wake parameters are populated before the hook is armed.
- The final wrapper is 2,392 bytes, contains exactly one parameter patch
  marker, and has no final ELF relocations.
- The HV shellcode is 6,168 bytes and fits its `0x2000`-byte reservation.
- The embedded wrapper and shellcode bytes match their separately built blobs.
- Clean builds are deterministic for the four recorded candidate artifacts;
  the outer payload uses a content-derived build ID instead of the SDK's random
  UUID default.

## Remaining unverified risks

These are not cleared by compilation or disassembly:

- retained user-backed source pages must remain valid across S3;
- the kernel SMP rendezvous must be callable at this point in early resume;
- exactly 16 CPUs must reach the HV shellcode barrier;
- `stgi` still executes before the barrier, matching the inherited loader but
  reopening global interrupts before Linux owns the machine;
- the identity-CR3 transition and first HV-shellcode instructions have no
  hardware marker yet; and
- 11.60 display/VBIOS transmitter offsets are not available, so this is a
  headless-first candidate.
