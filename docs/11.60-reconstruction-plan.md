# Firmware 11.60 reconstruction plan

Date: 2026-10-15

This plan incorporates an independent audit of the failed pLinux-derived
candidate and binary-level reconstruction of Sonic's known-working 13.60 ELF.
It is a build plan, not a claim that Linux boots on 11.60.

## Decision

Start from the official `ps5-linux-loader` lineage. Preserve its coupled
rest/wake design and import only the 11.60 pieces already validated on hardware:
the Byepervisor resume hook, dynamic VMCB discovery, 16-of-16 NPT disable, and
per-core IST6 handling.

Do not continue extending the pLinux-derived MP-startup wake wrapper. It changed
the execution context and memory contract at the same time, making its repeated
post-initrd stop difficult to isolate.

## Required component split

The outer ELF remains one coupled payload, but it installs two components with
different jobs:

1. The root-0 AP payload at physical `0x3ffff000` discovers the 16 GameOS VMCBs
   and disables nested paging. It does not stage or start Linux.
2. The kernel wake shellcode runs from the S3 wake path. It patches the live HV
   exit path, creates the low identity mapping, installs the HV transition,
   copies `linux_info`, bzImage, and initrd from their preinstalled kernel
   aliases, rendezvouses all CPUs on `vmmcall(1)`, and enters Linux.

The userland sequence should remain:

```text
setup_env
  -> fetch_linux
  -> prepare_resume
  -> hv_defeat_1160
  -> sleep(5)
  -> enter_rest_mode
  -> sleep forever
```

There is no resumed-userland Linux-launch phase.

## Component inventory

| Class | Component | Treatment |
|---|---|---|
| Reuse | 11.60 MP-startup hook and offsets | Lift from the hardware-validated branch |
| Reuse | Dynamic VMCB discovery and NPT disable | Keep as the AP payload's only job |
| Reuse | Per-core IST6 handling | Preserve the validated fix |
| Port | Official loader skeleton and main sequence | Retain the known-good coupled ordering |
| Port | `fetch_linux` page installation | Install a kernel alias for every 16 KiB image page |
| Port | `prepare_resume` | Install and verify the separate kernel wake shellcode before arming rest mode |
| Adapt | 11.60 S3/HV arm | Combine the validated AP strike with the original wake-shellcode redirect |
| Build | High-firmware kernel wake shellcode | Reconstruct the 11.60 HV patch, display handling, staging, rendezvous, and Linux transition |

The high-firmware kernel wake shellcode is the critical path. The public wake
shellcode predates this firmware family, while Sonic's extended implementation
is available only as a binary reference.

## Bounded bring-up

| Stage | Artifact | Pass gate | Status |
|---|---|---|---|
| 0 | Clean loader-only build | Complete both image reads and exit normally | **PASS** on 11.60; UI responsive |
| 1A | Reversible per-page kernel aliases | Install and verify all aliases, fully roll back, then exit normally | **PASS** on 11.60; 10,136 leaf PTEs verified and rolled back |
| 1B | Alias read-through diagnostic | Read a data canary through an exact mirrored syscore subtree, compare content and Accessed bits, fully roll back | **PASS** on 11.60; 16 KiB matched and four Accessed bits observed |
| 2 | Add `prepare_resume`, without arming rest | Install and verify every wake-shellcode page, then exit normally | Not started |
| 3 | Arm only the AP/VMCB step | Discover, change, and verify exactly 16 VMCBs | Prior harness evidence exists; not yet integrated into this tree |
| 4 | Add the complete S3 wake path | Reach an externally observable Linux-entry checkpoint | Not started |

Each stage should change one boundary and retain a durable or externally
captured result. Stage 0 validated the bounded image reads. Stage 1A confirmed
the 11.60 pmap offset, source translation, and transactional construction and
rollback of the official alias layout. Stage 1B then dereferenced one 16 KiB
NX data canary through the exact subtree mirrored into the current pmap,
observed all four hardware Accessed bits, and verified both PML4 roots restored.
It did not execute in PID 1, evict a cached translation, or stage executable
wake code. These results do not prove the previous wrapper's exact failure
cause.

## Open questions

- Revalidate the fixed physical addresses and bounds on a regular 11.60 console.
- Derive the 11.60 HV-patch bytes rather than transplanting 13.60 values.
- Derive or temporarily bypass firmware-specific display operations; early
  success may be headless or UART-only.
- Independently disassemble each subsequent ELF and compare its sequence and
  installed blobs with the 13.60 reference before a hardware send.

See the [Sonic 13.60 binary reference](sonic-13.60-reference.md) for observed
behavior and [Firmware 11.60 status](11.60-status.md) for the hardware evidence.
