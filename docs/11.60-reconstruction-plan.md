# Firmware 11.60 reconstruction plan

Date: 2026-10-15

This plan incorporates an independent audit of the failed pLinux-derived
candidate and binary-level reconstruction of Sonic's known-working 13.60 ELF.
It is a build plan, not a claim that Linux boots on 11.60.

## Decision

Start from the official `ps5-linux-loader` lineage. Preserve its coupled
rest/wake design and import only the 11.60 pieces already validated on hardware:
the Byepervisor resume hook, dynamic VMCB discovery, 16-of-16 NPT disable, and
per-core IST6 handling.

Do not continue extending the pLinux-derived MP-startup wake wrapper. It changed
the execution context and memory contract at the same time, making its repeated
post-initrd stop difficult to isolate.

## Required component split

The outer ELF remains one coupled payload, but it installs two components with
different jobs:

1. The root-0 AP payload at physical `0x3ffff000` discovers the 16 GameOS VMCBs
   and disables nested paging. It does not stage or start Linux.
2. The kernel wake shellcode runs from the S3 wake path. It patches the live HV
   exit path, creates the low identity mapping, installs the HV transition,
   copies `linux_info`, bzImage, and initrd from their preinstalled kernel
   aliases, rendezvouses all CPUs on `vmmcall(1)`, and enters Linux.

The userland sequence should remain:

```text
setup_env
  -> fetch_linux
  -> prepare_resume
  -> hv_defeat_1160
  -> sleep(5)
  -> enter_rest_mode
  -> sleep forever
```

There is no resumed-userland Linux-launch phase.

## Component inventory

| Class | Component | Treatment |
|---|---|---|
| Reuse | 11.60 MP-startup hook and offsets | Lift from the hardware-validated branch |
| Reuse | Dynamic VMCB discovery and NPT disable | Keep as the AP payload's only job |
| Reuse | Per-core IST6 handling | Preserve the validated fix |
| Port | Official loader skeleton and main sequence | Retain the known-good coupled ordering |
| Port | `fetch_linux` page installation | Install a kernel alias for every 16 KiB image page |
| Port | `prepare_resume` | Install and verify the separate kernel wake shellcode before arming rest mode |
| Adapt | 11.60 S3/HV arm | Combine the validated AP strike with the original wake-shellcode redirect |
| Build | High-firmware kernel wake shellcode | Reconstruct the 11.60 HV patch, display handling, staging, rendezvous, and Linux transition |

The high-firmware kernel wake shellcode is the critical path. The public wake
shellcode predates this firmware family, while Sonic's extended implementation
is available only as a binary reference.

## Bounded bring-up

| Stage | Artifact | Pass gate | Status |
|---|---|---|---|
| 0 | Clean loader-only build | Complete both image reads and exit normally | **PASS** on 11.60; UI responsive |
| 1A | Reversible per-page kernel aliases | Install and verify all aliases, fully roll back, then exit normally | **PASS** on 11.60; 10,136 leaf PTEs verified and rolled back |
| 1B | Alias read-through diagnostic | Read a data canary through an exact mirrored syscore subtree, compare content and Accessed bits, fully roll back | **PASS** on 11.60; 16 KiB matched and four Accessed bits observed |
| 2A | Exact-11.60 headless wake source and official staging | Preserve Sonic's `0x98` ABI and publish the inert blob at `kernel_cave_shellcode` through the existing PID-1 mapping path | **PASS**; exact 240-byte blob staged RX at `0xffff800000000000`, verified, and held with no hook/HV/rest/Linux path linked |
| 2B-0/1 | Read-only and owned-state carrier preflight | Verify alias backing, XOM gadget mappings, stock gate/TSS state, CPU pinning, and cave snapshot without arming | **PASS** on 11.60 |
| 2B-2 | Awake #DB carrier round trip | Trigger the selected CPU, verify provenance, and restore every modified carrier object | **PASS** on 11.60; UI responsive |
| 2B-3 | S3 resume provenance without alias execution | Enter the exact `startup_mp` resume wrapper, verify the selected frame, and restore GameOS | **PASS** after one Rest Mode cycle; UI responsive |
| 2B-4 | Direct PID-1 alias instruction fetch | `RET` once to the staged inert alias from the validated resume carrier | **FAIL** on wake; continuously pulsing blue light, no PASS marker |
| 2B-5 | Sonic-style ktext copy/execute diagnostic | Copy the inert staged entry to a bounded executable kernel-text carrier, transfer control there, and restore GameOS | Next bounded test; not yet built |
| 3 | Arm only the AP/VMCB step | Discover, change, and verify exactly 16 VMCBs | Prior harness evidence exists; not yet integrated into this tree |
| 4 | Add the complete S3 wake path | Reach an externally observable Linux-entry checkpoint | Not started |

Each stage should change one boundary and retain a durable or externally
captured result. Stage 0 validated the bounded image reads. Stage 1A confirmed
the 11.60 pmap offset, source translation, and transactional construction and
rollback of the official alias layout. Stage 1B then dereferenced one 16 KiB
NX data canary through the exact subtree mirrored into the current pmap,
observed all four hardware Accessed bits, and verified both PML4 roots restored.
It did not execute in PID 1, evict a cached translation, or stage executable
wake code. These results do not prove the previous wrapper's exact failure
cause.

Another inert `0x8000` carrier test would mostly repeat Stage 1B with eight
leaves instead of four. It would not exercise a new page-table level, execution
context, or translation-cache transition. Stage 2 therefore starts with the
real source candidate and advances to hardware only when a bounded probe path
can fetch instructions through its intended alias and return without touching
HV state, rest mode, display hardware, or Linux staging.

The probe artifact must publish code read-only and executable on first mapping,
publish arguments/status as read-write and NX, verify the complete readback,
invoke the entry exactly once through an already validated reversible trigger,
and independently restore the trigger plus both current and syscore root
entries. A new hook mechanism and a new wake blob must not be introduced in the
same hardware run.

The Stage 2A source scaffold is based directly on official commit
`64637c177eaed277fb6ccce394cbb29dd047b893`. Local source-port commit
`a3c1d304daf0e297511846cc9aaab3ced8397954` preserves the public `0x98`
argument ABI, NULL-preserves unavailable optional inputs, adds an exact-11.60
fail-closed branch, and provides a standalone RX-only diagnostic entry. The
entry is 240 bytes, contains one argument marker, has no relocations, calls, or
stores, and returns before UART, CFI, HV, display, rest, or Linux behavior. Its
SHA-256 is `2d7927fefb6c4465be13f632edeb810f159c3e2fb178f0d01f6d8a4aacfe8281`.
The Stage 2A outer ELF SHA-256 is
`38d913b5a484a89ae46f13c9fe1c078452e1c20adf6dd6b0091f45942ad15a8b`.
It mapped the entry RX in PID 1, verified four contiguous leaf PTEs and exact
byte readback, then held all backing. It did not execute the entry and is not a
boot-capable payload.

Live inspection rejected direct writes to the first candidate kernel-text page:
its PTE is `0x0400000018acb101`, or present, read-only, execute-only, and
executable. Stage 2B-0 through 2B-3 subsequently validated the 11.60 #DB carrier
and exact S3 resume provenance. Stage 2B-4 changed only the final transfer to a
direct `RET` into the PID-1 alias. The console hung on wake before a PASS marker,
while the otherwise identical non-fetch B3 path returned cleanly.

The supplied Sonic 13.60 ELF does not make that direct call. Its selected path
copies the prepared alias bytes into an executable kernel-text destination via
its supervisor-execute carrier and terminally transfers control there. Stage
2B-5 will reproduce only that bounded copy/execute boundary with the 240-byte
inert validator; it will not add HV defeat, Linux staging, or automatic Rest
Mode until the carrier itself returns cleanly.

## Open questions

- Revalidate the fixed physical addresses and bounds on a regular 11.60 console.
- Derive the 11.60 HV-patch bytes rather than transplanting 13.60 values.
- Reconstruct the supplied Sonic ELF's bounded supervisor copy from the staged
  alias into an audited 11.60 executable kernel-text destination, then execute
  only the inert 240-byte validator and restore the stock wrapper. The failed
  direct-alias `RET` must not be retried.
- Derive or temporarily bypass firmware-specific display operations; early
  success will be headless because the 11.60 UART override is also unresolved.
- Independently disassemble each subsequent ELF and compare its sequence and
  installed blobs with the 13.60 reference before a hardware send.

See the [Sonic 13.60 binary reference](sonic-13.60-reference.md) for observed
behavior and [Firmware 11.60 status](11.60-status.md) for the hardware evidence.
