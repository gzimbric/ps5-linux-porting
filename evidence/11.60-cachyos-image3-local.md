# Firmware 11.60 CachyOS image 3 local hardware test

Date: 2026-10-20

This was a local image 3 bring-up on the same CFI-1115B used for the earlier
11.60 runs. It is not a test of the separate public CI artifact and is not a
public-release hardware result.

The exact local image booted Linux 7.3.0 with a directly observed HDMI picture
and authenticated wired SSH. Its in-image Bluetooth kernel and userspace policy
also produced the first recorded internal-Bluetooth DualSense result for this
11.60 project. Wi-Fi menu and Steam desktop-switch results followed live
changes on the running system; those two changes were not present in the raw
image that was initially flashed.

## Boot and display

- Linux 7.3.0 reached authenticated userspace over wired SSH.
- The operator directly observed the HDMI picture.
- The bounded loader supplied the console's own IW620 firmware.

This confirms that this exact local raw image boots. It does not make the
different public CI image a hardware-tested artifact.

## Internal Bluetooth and DualSense

The local image rebuilt the hash-pinned Bazzite Deck v1.0.3 IW620 `btusb`
source correction in its own kernel and used the audited BlueZ policy. On
11.60:

- one internal Bluetooth controller was available;
- a DualSense paired, bonded, was marked trusted and connected;
- no USB DualSense was present for the input result; and
- buttons, motion sensors and touchpad input worked through
  `hid-playstation`.

A short check kept Bluetooth input working while Wi-Fi carried traffic. This
was not a 60-minute soak, and a cold-boot controller reconnect was not tested.

## Plasma Wi-Fi menu

The first normal GUI join failed with NetworkManager reporting that the access
point was not in the scan list. The IW620 driver and firmware were otherwise
healthy and scans returned access points. Live tracing showed that
NetworkManager changed the scan MAC address while KDE retained an access-point
object from the preceding scan.

The live fix was:

```ini
[device]
wifi.scan-rand-mac-address=no

[connection]
wifi.powersave=2
wifi.cloned-mac-address=permanent
```

After the adapter was returned to its permanent address, the normal Plasma
menu completed WPA3 association and DHCP. An HTTPS request explicitly bound to
Wi-Fi returned successfully. This is a hardware pass for the live policy, not
for the original raw image. Current source carries the exact tested settings.

## Steam Switch to Desktop

The image's original system-bus listener did not receive a matching request.
Steam remained on **Switching to Desktop**, and the next-session token did not
change. Manual `steamos-session-select plasma` followed by a tty1 getty restart
opened Plasma, proving that the selector, tty transition and display path
worked.

The launcher was then changed from:

```text
steam -gamepadui
```

to:

```text
steam -steamos -gamepadui
```

With `-steamos`, Steam's session integration intentionally used its legacy
selector fallback. The system journal recorded
`sudo /usr/bin/steamos-session-select plasma`; Gamescope exited, and
Plasma/KWin started. The built-in **Switch to Desktop** action therefore
passed through Steam's own selector path.

The live launcher change was not present in the raw image above. Current source
keeps `-steamos`, removes the unused listener and does not use `-steamos3`,
whose SteamOS-specific atomic-update behavior does not match CachyOS.

The reverse direction was then tested through a remote selector invocation.
Stopping the owning user `graphical-session.target` completed in 0.086 seconds;
KDE disappeared, Gamescope/Steam started and no overlapping compositor was
observed. Current source uses only that target stop, with no later process kill
or login-session termination. This proves the remote selector route, not yet a
result for the exact public prerelease artifact.

The actual desktop shortcut was then tested with the final 3,736-byte selector,
SHA-256
`1d099eeacc19bbf575e5a636fc81087a46f72af64390172e437372b493bde1c1`.
The watch log recorded the token changing from `plasma` to `gamescope` at
5.709 seconds. By 6.272 seconds, Gamescope was running while KWin and Plasma
shell were both absent: a 0.563-second handoff with no compositor overlap.
Together with the built-in Steam **Switch to Desktop** result, this is a full
live round-trip pass. These live changes were not in the original raw image.

## First-session follow-up

Current source opens Plasma on a freshly flashed image so the user can
configure networking before Steam's first Gaming Mode bootstrap. That new
first-session token was added after this raw image was built and has not yet
been tested from a fresh public artifact. Steam Offline Mode remains a
later-use test after Steam has completed setup online and saved the required
credentials and local game state.

## Evidence limits

- One console and one local raw image were tested.
- Wi-Fi and desktop-switch success followed live changes, so they are not
  properties of the original raw image.
- Bluetooth pairing/input is an in-image result, but reconnect and soak remain
  open.
- The live Steam-to-Plasma action and desktop-shortcut return both passed; the
  exact public artifact later reproduced the round trip in its separate test.
- Plasma-first startup passed on the public artifact; later Steam Offline Mode
  remains open.
- No new storage-integrity, video-decode, gameplay, thermal-equilibrium or
  long-duration stability claim is made by this test.
- The separate public CI artifact now has its own hardware evidence; none of it
  is relabeled as a result of this local image.
