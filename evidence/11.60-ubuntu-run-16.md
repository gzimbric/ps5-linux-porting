# Firmware 11.60 Ubuntu control boot

Date: 2026-10-18

Run 16 reused the byte-identical Run 15 loader on the same regular retail PS5,
but replaced the CachyOS system with an Ubuntu 24.04 image. The console reached
authenticated Ubuntu userspace over wired Ethernet and produced directly
observed physical display output after the rest/wake cycle.

This is cross-distribution validation of the published 11.60 loader path. Run
15 remains the loader baseline: Run 16 did not change the loader or independently
replicate the hardware result on another console.

## Tested inputs

| Input | Size | SHA-256 |
|---|---:|---|
| Run 15 loader ELF | 169,872 bytes | `422b87ec39ca0edfce8dddd609c2eff1cc7adcb2732b7909b76fafbd60dd2336` |
| `bzImage` | 12,702,720 bytes | `11280a8f5ca197ee5458fd446a4dadf2d0b5d0ef6218583cbe6325ee34e99cde` |
| Ubuntu initramfs before loader padding | 50,803,483 bytes | `996bc02a64404bc84d06c8df0c4143b66932d8af8549f39c82c71677fdec58c9` |
| EFI `initrd.img` consumed by the loader | 54,376,639 bytes | `2eef0352879e091083450b799c75514a450f4110cbc747f640962fdde2dc06c8` |
| `cmdline.txt` | 121 bytes | `6b3c09112fe049d3cbeada65fb3c82bb0f5fcaddce6c0709051df3d9f5a79f6d` |
| `vram.txt` | 11 bytes | `bc4642feb06a4cc6d10d5865e321efaad7ab3f3f1d5d025151b79978164310a0` |

The EFI initrd is the 50,803,483-byte Ubuntu initramfs followed by 3,573,156
zero bytes. This preserves the loader's 54,376,639-byte input gate, but its
content and SHA-256 differ from the successful Run 15 CachyOS initrd
(`c37b88569ef8f05b0b4ae432a8ec0fd323b7a3537a6441f8c45baaad45ff061f`).
Run 16 therefore does **not** reproduce the exact initrd in Issue #1 or replace
its documented recipe.

The command line was:

```text
root=LABEL=ubuntu2404 rw rootwait console=ttyTitania0 console=tty0 consoleblank=0 mitigations=off idle=halt preempt=full
```

## Direct observations

- The pre-rest loader path read the complete kernel and EFI initrd, installed
  and verified all 16,384 alias leaf PTEs, completed its carrier mutations, and
  armed the 11.60 Sonic-style wake chain.
- After wake, the console reached a steady white light, TCP port 22 became
  reachable, and an authenticated session confirmed Ubuntu 24.04.5 LTS with
  Linux 7.1.7.
- The operator directly observed the Ubuntu desktop on the attached display.
  The authenticated session independently reported `card0-DP-1` connected and
  enabled with DPMS `On`, a 1920x1080 mode, `amdgpudrmfb`, and an active
  GDM/GNOME Wayland session.
- The root filesystem on `/dev/sda1` mounted read/write and expanded to the
  available USB media. The EFI partition on `/dev/sda2` mounted read/write at
  `/boot/efi`.
- Wired Ethernet came up through NetworkManager with a DHCP address and a
  working default route. SSH, NetworkManager, GDM, the AMDGPU reprobe unit, and
  the fan-control unit were active or completed successfully. The fan unit
  reported that it selected its maximum setting.
- The system exposed 16 logical CPUs and about 15 GiB of RAM. The captured
  kernel log contained no panic or oops, and `systemctl --failed` reported no
  failed system units.

Authenticated userspace and direct display observation are the pass gates.
The steady white light and DRM state corroborate the result but would not, by
themselves, prove visible output.

## Wireless hardware result

The console's wireless function identifies as Marvell hardware, not a MediaTek
MT7921 device:

| Function | Identifier |
|---|---|
| PCI wireless function | `1b4b:2b56` |
| USB Bluetooth/WLAN companion | `1286:2059` |

No WLAN interface appeared, and the installed kernel exposed no module alias
for the PCI device. The `ps5-mt7921-wifi` mt76/MT7921 driver cannot bind these
IDs and is not applicable to this console. The pairing is consistent with the
[PS5 IW620 mwifiex path](https://github.com/ps5-linux/ps5-linux-mwifiex), which
is the correct direction for further wireless work.

## Evidence limits

- This is one Ubuntu boot on the same console used for Run 15, not a
  repeatability campaign or independent hardware reproduction.
- No physical UART was available, so individual MP3 and display-table returns
  remain unobserved.
- The sender retained the connection after its pre-rest output and eventually
  reached its bounded idle timeout. The authenticated post-wake session and
  visible desktop establish the boot result; the sender timeout is not a
  console failure.
- Raw captures are not published because they contain private network and host
  details.
