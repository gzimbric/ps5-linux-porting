# Firmware 11.60 CI Ubuntu image with the DMA E820 build

Date: 2026-10-19

Run 19 booted the image and ELF from the
[tester guide](../docs/ubuntu2404-tester-guide.md): the CI-built Ubuntu 24.04
image from release `ubuntu2404-1160-build-3` and the DMA E820 loader ELF from
release `firmware-11.60-dma-e820-run18`. It ran on the console used for Runs 15
to 18. The operator directly observed the HDMI picture, SSH worked over wired
Ethernet, Linux received the intended e820 map, and the checks in the guide
passed, including its optional I/O check.

This is the first recorded hardware boot of a CI-built Ubuntu image, and the
first recorded boot of the DMA E820 build with a directly observed picture.
Run 18 remains the hardware validation of the DMA E820 build, and Run 15
remains the release baseline. The read/write errors reported by testers were
not reproduced here.

## Boot

The console was the same regular PS5 used for Runs 15 to 18: a CFI-1115B,
original model, digital edition, on retail 11.60.

After a cold boot and the kernel exploit, the DMA ELF was sent once to the
`ps5-payload-sdk` ELF loader on port 9021. Exactly 169,872 bytes were sent.

The loader printed 2,832 bytes, byte-identical to its output in Run 18 and so
to Runs 16 and 17. The output includes
`PS5 WiFi firmware offset missing for firmware 1160` and
`Something went wrong while dumping device firmwares - Continuing`. Both are
expected: the 11.60 build has no Wi-Fi firmware offset, and the same lines
appeared in Runs 16 to 18. The output also includes
`11.60 Sonic-style Linux wake chain armed`.

The console entered Rest Mode on its own. The operator woke it with the
controller's PS button on the first try. The light turned white, and TCP port
22 opened about 20 seconds after the wake was reported.

## Direct observations

Ubuntu 24.04.5 LTS started with Linux 7.1.7 and this command line:

```text
root=LABEL=ubuntu2404 rw rootwait console=ttyTitania0 console=tty0 consoleblank=0 mitigations=off idle=halt preempt=full
```

The e820 map passed to Linux contained these lines (others omitted):

```text
BIOS-e820: [mem 0x0000000000100000-0x0000000000ffffff]  System RAM
BIOS-e820: [mem 0x0000000001000000-0x000000003fffffff]  device reserved
BIOS-e820: [mem 0x0000000040000000-0x000000005fffffff]  System RAM
```

This is the intended reservation. The full table had the same lines as in Run
18.

### Display

The operator directly observed the picture on the HDMI monitor. DRM also
reported `card0-DP-1` connected and enabled with a 1920x1080 mode, and GDM was
active with a GNOME session logged in automatically on `seat0`. Run 19 is
counted as a visible-display result because the picture was observed directly.
The DRM state only corroborates it.

### System

- The operator added an SSH key using the image's initial `ps5` / `ubuntu`
  login. The checks ran over key-based SSH on wired Ethernet, the only network
  path, since the image has no Wi-Fi driver or firmware. The image gives the
  `ps5` user passwordless sudo by design (`/etc/sudoers.d/90-ps5-control` in
  the profile).
- `MemTotal` was 14,783,608 kB, identical to Run 18. `HardwareCorrupted` was
  0 kB. A 7 GiB zram swap was active.
- `/dev/sda1`, the ext4 `ubuntu2404` root, had grown to 230.6 GB and was
  mounted at `/`. `/dev/sda2`, the 499 MB FAT `boot` partition, was mounted at
  `/boot/efi`.
- `ssh`, NetworkManager, `gdm`, `ps5fan`, `ps5-amdgpu-reprobe`, and
  `ps5-boot-report.timer` were active. The first-boot unit had finished and
  was inactive. `systemctl --failed` listed nothing.
- The kernel taint value was 64, the same as in Runs 17 and 18. The
  out-of-tree Wi-Fi modules are not installed in this image.

## Tester guide checks

The checks in the [tester guide](../docs/ubuntu2404-tester-guide.md) were run
exactly as written at commit `cf877f4`.

| Step | Check | Result |
|---|---|---|
| 1 | Memory map | Pass; the `device reserved` line for `0x0000000001000000-0x000000003fffffff` was present |
| 2 | Memory size | About 14 GiB |
| 3 | Kernel, command line, and drive layout | As expected |
| 4 | Storage error grep | No lines for the whole boot |
| 5 | Optional I/O check | Pass (below) |

Step 6 is for testers who saw read/write errors with the old loader. There
were none to repeat on this console.

### I/O check

The script was copied verbatim from the guide (SHA-256 of the script
`7bc68fa14c1875cb07b9dde5c00c95edec2b1d1d441ff756ffd929bfb720aa52`) and run
with `sudo`. It reported 221 GiB free under `/var/tmp` and wrote three 4 GiB
files, each in 20 seconds. It then dropped the page cache, re-read all three
files in 44 seconds, and all three hashes matched. No storage error lines were
logged during the test. It printed `Result: PASS (3 x 4 GiB)` and removed its
files. The whole check took 1 minute 45 seconds.

### Kernel log scan

A scan of the kernel log for the whole boot found no Buffer I/O errors,
`blk_update_request` errors, `uas_eh` lines, AMD-Vi faults, DMAR lines,
machine checks, or BUG, Oops, or Call Trace lines.

## Warnings

These lines appeared in the log. None of them stopped the boot or the checks.

- `ahci_salina_drv 0000:40:00.3: Salina SATA PHY init failed: -110`. This was
  also in Run 16. The console is a digital edition with no disc drive.
- amdgpu `Fence fallback timer expired on ring sdma0`, twice at about 6 seconds
  of uptime. This was also in Run 16.
- Bluetooth opcode messages from `hci0` and `hci1` at boot.
- systemd logged `basic.target: Found ordering cycle on sockets.target/start`
  involving `ssh.socket` and `ps5-ssh-host-keys.service`, and deleted the
  `sockets.target` job to break the cycle. SSH still worked. This was not seen
  in Run 16.
- GNOME session scope and keyring start failures in the journal. These are
  desktop noise.

## Image defects

Two defects were found in the build 3 image. Neither blocked the boot or SSH.
Both are in the Ubuntu image profile and are tracked in the
[maintenance backlog](../docs/maintenance-backlog.md#run-19-ci-ubuntu-image).

1. The hostname is the 12-character ID of the CI build container, written into
   `/etc/hostname` when the image was built. The Run 16 image also had a
   container-ID hostname, so this is a profile issue and not new to CI.
2. The `ps5-ssh-host-keys.service` ordering cycle listed under warnings. It was
   not seen in Run 16.

## Evidence limits

- This is one boot on the same console used for Runs 15 to 18, not a
  repeatability campaign or independent hardware reproduction. Other models,
  including the disc edition and the Slim, have not been tested.
- There is no A/B control. The Run 15 ELF was not booted with this image or
  put through the same I/O check, and the testers' read/write errors were not
  reproduced here. Run 19 does not show that the reservation fixes them.
- The I/O check was short: 12 GiB on the USB root only, in under 2 minutes.
  There was no soak, no M.2 or NVMe storage, no sustained GPU load, and no
  repeat boot.
- Wi-Fi was not tested; the image has no driver or firmware for it. Bluetooth
  was not tested.
- Only build 3 was tested. A later CI build has a different root filesystem
  and image hash and needs its own boot.
- Raw logs are not published because they contain addresses and machine
  identifiers.
